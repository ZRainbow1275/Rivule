# 领取之后，发送之前

| 阶段 | 核对 | 写入 |
|---|---|---|
| 主 Agent 比较席位 | 地区、能力、占用、预算 | 无 |
| 对选中席位复核，领取 | 当前授权、席位、预算版本、原任务和原文摘要 | 租约；不能发 |
| 对同一租约再次复核，开始 | 同一主持者、席位、提供方、通道、处理地区、预算和输入；当前版本、租期与围栏 | 开始事件和 outbox 一起提交 |

预算或授权变了，即使看板修订号没动，原选择也会被拒。已经领取但未发送的任务保留租约，期满后才能重新核选；另一席位可处理独立任务。提交失败会同时回滚开始事件和 outbox。重复提交已成功持久化的同一开始事件不返回第二张发放许可。

`storage/sql-journal.mjs` 的 `reviewedDispatch` 默认不配置。实验配置下，`inspectChoice` 返回对主持者、作用域、任务、此前围栏、席位路由和审查事实做绑定的比较值；持有它不赋权。`claimChoice` 与 `beginChoice` 各自在同一权威事务读取宿主提供的当前事实，而不是信任客户端、缓存或原先的读回。传入请求只是供宿主验证身份的上下文；宿主须把选择范围、发放权限和专用测试账号绑定到解析器，保证权限或预算变更更新相应代次，且解析和变更在同一事务域。选中标记仅供宿主流程，公开看板仍只有既有别名和汇总状态。存储只保存别名、主持者别名、代次和摘要，不保存原文、密钥或账号凭证。

这组试验保护经该入口领取的租约。旧的内部 API 和此前实验仍可读取和重放；正式采用时应只开放已复核的入口，另审计能写原始账本的宿主权限。已核预算指宿主给出的当前审查结论，不扣费，不分配跨任务余额。模拟发放许可只在已提交当下有效；没有实际发送器，也未解决提交到外部发送之间的撤权窗口，正式发送前须由对应执行器另做即时授权和回执核对。没有真实 PA 或生产部署。

验证：`node --test tests/reviewed-dispatch.test.mjs`。使用两个实际连接同一临时 SQLite，测试授权变化、换路、预算变化、错误原文、过期重选、故障回滚、重复 begin 和独立并发。

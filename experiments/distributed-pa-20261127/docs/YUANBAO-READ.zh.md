# 元宝只读看板候选

同一版账本，同一套读规则。元宝、个人 Muse 的状态读入口与主看板对同一授权范围调用同一投影，三方都将「已收到」「已交稿」「已验收」分别显示。MCP 给受限查询，Skill 定义什么时候查、允许说什么。主 Agent 才能验收，依赖只看前置验收状态。

`yuanbao/read-board.mjs` 仅提供两个工具，解析调用身份、代号映射和授权全部由服务端决定；读完再复核一次身份与可见范围，避免撤权发生在读中途。受限席位返回安全代号、状态/证据类型、校验标记和授权范围内的依赖。未交付 OAuth 服务、真正聊天卡片或上线包。示例只允许一个隔离且全部为合成数据的看板；多租户拿真实数据前需要单租户版本、审计和区域审查。

`yuanbao/SKILL.md` 是指令样稿。使用合格企业单独绑定真实 OAuth MCP 地址、只勾选两个工具以后，再在腾讯元宝按官方格式跑对话评测。不要把令牌放进 Skill，也不要让元宝对 Rivule 排他席位执行重发。26 个离线应用与授权用例，本地通过。多轮及触发用例由脚本模拟，产品真实自然语言理解、模型、登录和企业审核均未试。

### 分配视图的校验标记

受限席位只收到已授权的任务代号、状态与可见依赖。响应不含事件序号、卡片绝对版本、内部 ID 或更新时间；同一任务的回包不因未请求的卡片改变。返回的 `validator` 只用于比较本次可见结果，绑定服务端签发的授权代次、席位与视图，不能作为令牌、放行证据或跨席位共享。私有样本需显式传入主机管理的独立 32 字节以上密钥，以便重启后在相同授权与数据上保持标记稳定。刷新每次重验授权；撤销再授权必须由宿主产生新代次。只有同时被确认是 owner 且明确握有全局读权限 `pa:board:read_global` 的调用才保留内用的全局版本与时钟。

这是离线实验。原记录的绝对序号继续用于内部并发和事务，不给受限观察工具。这里没有 HTTP 304、通知、SSE 回放或实账号联网；旧版 Muse 分配写入桥是另一条实验路径，尚未迁移其绝对版本协议。

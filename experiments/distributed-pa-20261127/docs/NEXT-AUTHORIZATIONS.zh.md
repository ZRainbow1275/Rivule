# 下一轮接入决策

先不填账户与凭据。公开能力、Rivule 离线验证、实际绑定、真实往返分别记录；一次走通也不等于开放任意派工。

| 决策 | 我的默认建议 | 为什么要本人决定 |
| --- | --- | --- |
| 第一个个人 PA | 可用的 Tasklet 授权席位，或已持有的专用 Manus Cue。Tasklet 先只核对所选 Agent 与真实工具结构；Cue 需要先核 Key 权限和独立线程。 | OAuth 有范围，派工可能花积分。选自己控制的账号，不要在聊天粘 Key。 |
| 第一个国内派工 | 已有环境的百度搭子 DuMate，只有在确有可用租户和预算时才排实际短任务；否则先评估飞书 Aily 或自托管 QwenPaw。 | 对企业权限、实际运行地域和费用做独立核验，不能靠产品名代替。 |
| Muse 多席位 | 先两个确实独立授权的席位，各领不同任务，做最小权限。只用于并行，限额时原席位等待。 | 每个个人 Connector 只能由授权身份自己绑定；不借账号共享或轮换过限制。 |
| 只能手工的产品 | 小豆先用人工复制/粘回，Rivule 将它列作“人工回传，待验”；新找到正式接口再升级。 | 不使用未公开端点、代操作登录或自动绕流程。 |
| 数据与费用 | 严格用公开产品说明，附件和私有上下文关闭，支出不默默启动。确认处理、留存、日志位置以后再谈私有路线。 | 日志和模型区和连接器所在地可能不同，团队授权也可能与个人权限不同。 |

首测不需要先决定 40 个产品：选一条国内、一条国际；主 Agent 将同一份公开材料拆成两件不同交付物。一个分支故障不阻止另一个交稿，但两份都由主 Agent 验过才能合稿。确认失败时查原尝试，不自动重发。从这条路线拿到实际回执后，再依接口族扩大覆盖。

# Integration acceptance matrix

A familiar name or icon does not prove a connected PA. Use the authenticated current source/key/configuration generation and valid verification evidence. Revocation and changed bindings invalidate old verification. Keep historical tasks with a re-verification label.

| Integration | Included implementation | Acceptance boundary |
|---|---|---|
| dot / authenticated MCP source | Event publishing, receipts, source-scoped snapshot | Current production flow exercised; a new installation needs its own OAuth and publish/read checks |
| Gemini Spark | Shared source contract, product name and neutral S badge | No universal client compatibility claim; perform initialize/tools list/read and publish/receipt checks for each connection |
| Muse | Authenticated API path and current-binding checks | API enabled/key binding plus own accepted receipt/read-probe rules; no claim every client configuration is accepted |
| Other assistants | Generic authenticated contracts | Unverified until that exact connection is tested; no Kimi/Grok support promise |
| QQ | Binding, fixed passive reply, diagnostic classifications and owner-click one-shot active probe | Passive reply success is not active permission; ongoing active delivery is not enabled by this package |

Task snapshot accepts an exact project/task/run/branch. Null source_seq can yield initialize_sequence/next_seq=0 when eligible; the suggestion is not a reservation or compare-and-swap. Preserve sequence conflicts and approval protections. Never guess a sequence or create a different branch to evade a conflict.

QQ active API omits msg_id/event_id; wakeup is a separate mode. The passive documentation has a 60-minute prose / 5-minute parameter discrepancy: current fixed reply uses a conservative 5-minute check. The reviewed one-shot active probe is included; it does not activate general continuous delivery. The bot profile card's active-message switch is controlled by the user. Do not populate proactive evidence manually.

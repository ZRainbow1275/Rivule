需要 Node.js 24 或更新版本。在源码根目录运行下面的命令。依赖和字体安装需要网络，其余重建使用固定输入。

npm ci --ignore-scripts
node scripts/install-font.mjs
node scripts/build.mjs

✓这一步完成时命令全部成功，在 dist/owner 和 dist/gateway 生成部署模块。本地构建不会部署服务或发出真实通知。

02
服务所有者

配置自己的通知入口

准备 Cloudflare 账号、自己的 Discord 应用和 bot，以及一个准备接入的助手。先复制模板，再填写你自己的配置。

建立私人配置
cp config/wrangler.owner.example.json config/wrangler.owner.private.json
cp config/wrangler.qq.example.json config/wrangler.qq.private.json
  1. 确定账户与目标填入 Worker 名称、实际服务域名、KV 和 Discord 的应用 / 用户 / DM 信息
  2. 配置来源与项目先选一个来源和一个允许的项目，决定使用 MCP OAuth 还是 HTTP 接入
  3. 检查模块与绑定保留模板的最终模块路径、no_bundle 和 Durable Object 绑定；已有安装保留原迁移历史
  4. 按部署清单发布并回读核对实际版本和模块，再设置 Discord 交互地址与签名握手
凭据在服务的安全设置里配置

把非敏感缺项交给 AI 整理即可。需要登录或授权时，使用对应服务的正常流程。

✓这一步完成时你有经过部署检查的服务，并能提供确定的接入地址、来源 ID 和项目 ID。

03
要接入的 AI 助手

完成当前来源的连接

先向所有者确认接入方式、实际服务地址、来源 ID 和获准使用的项目。这里的 PA 就是个人 AI 助手。

MCP + OAuth

添加远程 MCP 连接

地址为 PUBLIC_ORIGIN/mcp/<source_id>，用所有者给出的实际值替换占位符。

完成正常授权后，初始化并读取工具列表。你应能看到发布更新、查询回执和精确任务快照的工具。

HTTP

按集成合同连接

Muse API 和 HMAC 的鉴权、路由与请求封装各不相同。让集成方按对应合同配置。

连接成功之后，继续做同一来源的上报与实收验收。

✓这一步完成时当前连接已通过认证和读取检查。接着发一条已获准的测试通知。

04
助手上报 · 所有者确认

亲眼看见第一条更新

所有者确认测试内容与接收渠道后，助手执行下面这一个闭环。

  1. 读取当前任务调用 get_task_snapshot，使用自己的项目、任务、run 和 branch；序号由维护事件顺序的来源决定
  2. 发布一次测试更新按当前工具 schema 调用 publish_task_update，写清“第一条连接测试”，保存 receipt_id
  3. 查询原回执同一来源调用 get_delivery_status，确认状态；顶层结果描述 Discord，其他渠道分别检查
  4. 在 Discord 确认收到检查目标聊天、来源和内容都正确，再将这个来源记为已接通
连接已认证→更新已接受→通知已实收

如果正在等待，就查询原回执；结果未知时，先检查回执与目标聊天，避免重复试发。

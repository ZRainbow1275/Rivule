# 离线构建与模块闭包验证

先按[安装与构建](../README.md#build)安装锁定依赖并恢复字体。构建使用仓库已锁定的 TypeScript 解析器检查 JavaScript，不额外下载工具，也不执行源码模块。

```sh
npm run check
node --test tests/build-module-closure.test.mjs
npm test
npm run build
```

## 构建内容与失败条件

- 入口为 `src/owner/worker.js`、`src/gateway/worker.mjs`，以及 `src/sdk` 下递归发现的所有 `.js` / `.mjs` 模块。新增 SDK 或入口引用的模块不需要再更新复制清单。
- 递归跟随静态导入、仅副作用导入、具名 / 星号重新导出，以及使用字符串或无插值模板字面量的动态导入；模块循环受支持。注释、字符串和嵌入的 HTML 文本不会被误认为模块引用。
- 普通模块保留 `src` 内的相对路径，复制到 `dist`。`owner/font.otf` 和 `owner/renderer.wasm` 由原有固定资源提供，构建前必须分别通过既定 SHA-256 校验。二进制资源之外的依赖必须是 `.js` / `.mjs`。
- `cloudflare:workers` 是明确允许的运行时外部模块。本项目按 no-bundle 方式部署，未知包名或其他外部模块不会被静默忽略；如未来需要它们，应先设计对应的打包与运行时支持。
- 缺失文件、源码语法错误、越出源码根目录的引用、跨根目录符号链接、含查询 / 片段 / 反斜杠的引用均会报错。动态导入使用变量、字符串拼接或插值模板时也会报错，因为构建无法证明其完整依赖。

## 不依赖旧产物

构建先收集源码图，在新的临时目录写入文件，再从这些实际输出文件重新解析完整依赖图并比较内容。验证成功后才替换整个 `dist/`；资源或依赖验证失败时，已有 `dist/` 保持原样。旧目录中的孤立文件不能补足源码缺失的依赖。

产物包括 `dist/owner`、`dist/gateway` 和 `dist/sdk`。SDK 可能引用 `dist/owner` 中的共享模块，分发时须保留其依赖与相对目录，不能只复制单个 SDK 文件。

`dist/` 整体属于生成目录。若也需要静态展示页，在模块构建后运行 `npm run build:showcase`；先生成的展示页会在下一次模块构建时一并被替换。

## 回归证明的范围

`tests/build-module-closure.test.mjs` 将实际生产源码复制到隔离目录，从不存在的 `dist/` 开始运行真正的构建命令。它再使用独立的 Node 模块链接器检查 owner、gateway、所有会话 v2 模块和两个 SDK 的静态导入 / 导出，实际导入两个输出 SDK，并核验输出资源哈希。链接器只替代 Cloudflare 运行时接口与二进制叶节点，不替代任何相对 JavaScript 依赖，也不执行 Worker。

其他回归检查动态导入目标、嵌套 SDK、模块循环、旧文件清理，以及缺失依赖、非字面量动态导入、错误入口、错误语法和资源损坏时的失败路径。它们不访问网络、不部署服务、不发送通知。模块链接成功不是 Cloudflare 部署、浏览器界面或生产实收的验证结果。

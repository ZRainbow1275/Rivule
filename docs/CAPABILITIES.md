# 当前能力

## 助手与 Discord

提供 MCP OAuth 与 HTTP 接入方式。接入前确认助手或集成方支持所需协议，再为每个来源分别完成认证、发布、回执与接收方实收确认。

Discord 提供来源筛选、任务总览与详情、进展和待决定通知。助手需明确上报变化。认证来源可读取自己的精确项目、任务、run 与 branch 快照，不能借此发现其他来源的任务。

## QQ

支持固定回复、所有者点击的一次性主动验证、会话内持续通知、暂停与容量提示。公开模板默认关闭发送，持续通知需所有者确认当前接收账户、权限与本轮开启。

连接时长默认仅提醒，120 分钟是可调整的每日阈值，不是强制停止时间；可在「运行预算」选择到点暂停。主动通知上限 100 次，最小间隔 3 秒。当前来源与会话证明、配额、容量及去重检查共同约束发送。未知结果不自动重试。连接时长不是 Cloudflare 账单额度；尚无跨会话自动续权或 Discord 全功能对齐。

## 读取边界

任务快照读取不写入来源证明或通知队列。回执与诊断读取不会初始化发送队列或调度通知；成功认证读取可能刷新已有连接证明，初始化和工具列表可建立证明。健康探针有独立副作用，不能等同任务快照。

## 安装范围

首次自托管仍需手动配置 Cloudflare、Discord 与来源认证；每个安装都需自行完成连接与实收检查。静态展示使用虚构内容，不连接服务。

## 新源码：双向桥接的阶段边界

当前开发分支新增任务上下文消息桥接与原 PA 指令队列，尚未进行生产部署或实收验收。默认只接收任务上报；每次任务回复、指令回传和 QQ 回复类别分别由所有者显式选择。管理权限有效期不是持续转发授权有效期。

Discord 使用已送达指定任务卡或回复卡的按钮/表单，QQ 使用已送达消息里的明确上下文代码。不会将任意聊天文本猜成给某个 PA 的指令。来源主动 claim/ack，失联领取进入 unknown 且不重新发放，不替来源执行敏感动作。来源不可更改所有者转发偏好。

普通对话没有 task/run/branch 时，当前协议明确不支持。后续应新增独立 conversation 上下文类型、来源操作范围和所有者授权，不能复用项目任务授权或虚构任务 ID。代码不承诺全局拦截各提供商所有响应，不绕过来源自身策略。
